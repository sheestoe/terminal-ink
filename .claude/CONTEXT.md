# TRMNL Node Lite - Durable Context

## Hardware Awareness (CRITICAL)
- **Device Context**: The user is using a **Kindle** (or custom e-ink hardware referred to as a Kindle), **NOT an official TRMNL device**. 
- Never assume official TRMNL hardware features, setup procedures (like AP mode / 192.168.4.1), or access to the TRMNL administrative dashboard. Everything must be handled via our own BYOS (Bring Your Own Server) Node.js implementation and scripts (like TRMNL_config.sh).
## Deployment & Redis
- **Render Delays**: Render free-tier deployments take 3-5 minutes to roll out. When pushing code or schema changes (like Upstash Redis keys), do not assume they are live immediately. Always verify the Render dashboard before concluding a feature is broken.
- **Upstash Redis Schema**:
  - config:rotation (List) -> e.g. ["weather", "news"]. Used for infinite plugin rotation.
  - config:override (String + TTL) -> Intercepts the display immediately and expires on its own.
  - data:<plugin> (JSON string) -> Background Cron cache. Never make live API calls on the /image route to prevent Kindle timeouts.

## PowerShell & Code Editing
- **PowerShell String Replacement Gotchas**: Be extremely careful using Get-Content -Raw and -replace for multi-line code modifications on Windows. PowerShell mishandles \r\n (CRLF) vs \n (LF) depending on git settings, often duplicating code or failing regex matches. Prefer AST-aware tools, precise line-number replacements, or python scripts for robust text manipulation.
- **PowerShell String Interpolation**: When injecting TypeScript code via Set-Content in PowerShell, ALWAYS use single quotes @' ... '@ instead of double quotes @" ... "@. Double quotes will silently consume $var and backticks, breaking JS template literals.
